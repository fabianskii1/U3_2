# 정비 보고서 프론트엔드 변경 내역

2026-11-19. 변경 범위는 `U3_2/fe`다. BE·AI·DB 코드와 데이터는 변경하지 않는다.

## 화면에서 확인하기

기존 방식으로 프론트를 실행한 뒤 상단 **보고서** 메뉴를 연다. 기존 목록의 보고서를 열면 조회 모드로 상세를 보여 준다. **수정 → 임시 저장**으로 변경하고 다시 열어 확인할 수 있다. **예시 보고서 열기**는 씰 누출 상황의 합성 알람·센서·AI 후보를 담은 별도 초안을 만든다. 실제 점검·조치·확정 원인은 비어 있다.

공통 상단 메뉴, 설비 탐색 트리, 선택 필터, Skadi Assistant, 보고서 경로(`/reports`, `/reports/new`, `/reports/:reportId`)는 유지한다. 보고서 목록에는 ID, 설비명·ID, 발생 알람, AI 추정/최종 원인, 작성 상태, 작성일을 표시한다. 기존 설비·기간 필터와 정렬·페이지 이동을 유지한다.

## 구현한 업무 흐름

1. **사건 및 설비 정보**: 연결 가능한 알람·설비 위치·등록 정비 이력을 불러온다. 새 보고서는 선택 설비의 최근 저장 알람(또는 URL의 `alarm_id`)을 기준으로 초안을 만든다. 기존 보고서에는 설비만 같다는 이유로 최근 알람을 끼워 넣지 않는다. 펌프 제조사·모델, 당시 운전 조건처럼 현재 API에 없는 항목은 수기 입력으로 남긴다.
2. **관측 증상 및 운전 영향**: 수정 가능한 텍스트, 관련 센서 선택, 알람 전후 그래프, 단위별 개별 축, 시점 선·이후 확인 구간 음영, 센서 표시 토글, 시간 범위, 전후 값 요약을 제공한다. 원격 모드에서는 기존 `/api/trend`를 사용하고, 실제 데이터가 없거나 조회 실패하면 그 상태를 표시한다. 예시 데이터는 별도의 예시 보고서에서만 사용한다. 최초 조회한 관련 센서 시계열은 원본 스냅샷에 보존한다.
3. **진단 및 원인 확인**: AI 초기 순위를 읽기 전용 원본으로 보관하고 각 후보를 미확인/확인 중/제외/확인됨으로 관리한다. 현장 점검 행에 대상 원인, 방법, 일시, 결과·제외 근거, 증거 ID, 사진·확인 자료 URL을 기록한다. AI 1순위를 자동 선택하거나 확정하지 않는다. 2·3순위 또는 기타 직접 입력을 선택하고 해당 원인의 점검 결과와 확정 근거가 있어야 원인 확정이 가능하다. 확인 근거·후보 상태·관련 관측을 바꾸면 원인 확정을 해제한다.
4. **실제 수행 조치**: 왼쪽 등록 매뉴얼/권장 자료와 오른쪽 작업자의 실제 조치를 구분한다. 실제 작업오더, 작업자, 시작·완료 시각, 수행 내용, 교체 부품·수량을 직접 입력한다. 매뉴얼·채팅의 추천을 실제 수행 내용으로 자동 복사하지 않는다.
5. **출처 및 기록 검토**: 센서/CSV 구간, 증거·문서 URL, 과거 정비 사례 ID, 기록자·검토자, 등록 시각, 검토 상태를 보관한다. 연결 가능한 안전한 문서 URL만 클릭해 열 수 있다.

최종 보고서 확정에는 현장 원인 확정, 실제 수행 내용, 작업자·작업 시각, 기록자가 필요하다. 확정 확인창에서 선택 원인과 실제 조치를 다시 확인한다. 확정 보고서는 편집과 채팅 덮어쓰기를 잠그며, 수정하려면 사유를 입력한다. 이전 확정 상태 전체를 스냅샷으로 기록하고 재확정을 요구한다. 취소 시 마지막 저장 상태 전체로 복원한다.

## 데이터와 저장

기존 `Report.values` 여섯 필드는 호환성을 위해 유지하고, 구조화된 `values.maintenance`를 추가했다. 사건 정보·관측·진단·실제 조치·기록 검토와 최초 알람/AI/센서 원본, 확정 상태, 수정 이력을 함께 저장한다. 기존 보고서 데이터는 상세를 열 때 확장 양식으로 변환하며, 기존 추정 원인과 조치 텍스트는 검증 여부를 알 수 있는 참고 기록으로 보존한다.

- 원격 모드: BE의 기존 보고서 조회 API를 유지하고, 확장 보고서 저장은 `localStorage`의 `skadi-maintenance-saved-v1`에 수행한다. **서버 저장과 팀 공유는 미지원**이며 화면에도 명시한다. 저장 시 미구현 POST/PUT API를 호출하지 않는다. 다른 탭의 최신 저장본이 있으면 버전 충돌로 보호한다.
- Mock 모드: 기존 프론트 Mock API와 파일 저장 구조를 그대로 사용해 확장 필드를 저장한다.
- 입력 복구본: 기존 Zustand 영속 저장 키 `skadi-report-drafts-v1`를 유지한다. 입력한 내용은 복구본에 반영되지만 새 확장 보고서의 저장·확정은 명시적인 버튼으로 수행한다. 기존 여섯 필드 보고서의 자동 저장 동작은 유지한다.
- 브라우저 저장 공간 부족을 성공으로 표시하지 않는다. 브라우저 데이터 삭제, 비공개 세션 종료, 다른 브라우저·기기로 이동하면 브라우저 저장본을 사용할 수 없다.
- 공통 채팅 문맥은 미저장 로컬 초안 ID도 전달한다. 채팅의 추정 원인·추천 조치는 참고 메모로 표시하고, 실제 수행 내용과 최종 원인에 자동 반영하지 않는다.

## 연결한 기존 읽기 API

- `GET /api/reports`, `GET /api/reports/{id}`: 기존 목록·상세
- `GET /api/alarms/history`: 초안의 설비별 알람 선택
- `GET /api/equipment/{id}`: 설비 위치
- `GET /api/equipment/{id}/manuals`: 등록 매뉴얼 제목과 원문 링크
- `GET /api/maintenance-histories?equipment_id=...`: 과거 정비 이력
- `GET /api/trend`: 관련 센서 시계열

## 이후 백엔드 연결이 필요한 항목

아래는 아직 구현·연결된 API가 아니다.

- 1~5번 전체 구조를 저장·조회·수정하는 보고서 API. 확정 상태와 수정 이력, 버전 충돌 계약을 포함해야 한다.
- 보고서/알람에 연결된 **실제 AI 진단 후보·초기 순위·관련 센서**를 제공하는 결과 API. 현재 BE에는 이 데이터가 없으므로 실제 보고서에 예시 후보를 넣지 않는다. 연결할 모델은 `maintenance.original.aiCandidates`와 관련 센서 스냅샷이다.
- 매뉴얼/RAG 결과의 권장 조치 본문, 문서번호·개정판·절·페이지.
- 증거 사진·문서 업로드와 접근 권한. 현재는 URL 연결을 지원한다.
- 작업자·기록자·검토자의 계정 연결, 서버 승인 및 공유, PDF 생성.

## 검증

- 프론트 빌드 및 TypeScript 확인 통과.
- 단위 테스트 통과.
- 보고서 브라우저 시나리오 5개 통과: AI 2순위 확정/기타 입력/저장·복원/채팅 연결/수정 충돌과 확정 후 이력.
- 실제 연결 모드를 테스트 응답으로 점검: 기존 보고서 목록·상세, 관련 센서 조회, 브라우저 저장과 새로고침, 1280px 화면, BE 쓰기 요청 0건, 브라우저 오류 0건.
- 전체 기존 브라우저 검사 중 설비 화면/개발 도구 관련 3건은 수정 전 원본에서도 같은 제목 선택자 오류로 실패한다. 해당 설비 화면과 테스트는 이번 보고서 작업에서 변경하지 않았다.
