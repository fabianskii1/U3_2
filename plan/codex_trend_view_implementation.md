# 채팅 결과 기반 Trend View 구현 계획

SKADI의 AI 채팅이 생성한 트렌드 링크를 DB에 저장된 조회 설정으로 열고, 사용자 질문·AI 응답·트렌드 결과의 관계를 추적한다. 구현 지침은 담당 영역별 문서로 분리했다.

1. [DB: 스키마와 마이그레이션](deeplink/db.md)
2. [BE: API, 저장 및 권한 검증](deeplink/be.md)
3. [FE: 채팅 링크와 트렌드 화면](deeplink/fe.md)
4. [AI: 질문 해석과 Tool 연동](deeplink/ai.md)

## 공통 원칙

- 먼저 실제 코드의 기술 스택, 인증, 채팅 메시지 구조, 센서 데이터 API, 마이그레이션 및 테스트 규칙을 확인한다. 문서의 테이블명과 API 경로는 제안이며 확인된 기존 구조에 맞춰 조정한다.
- 기존 채팅 저장/응답 흐름과 Trend 화면을 확장한다. 기능 범위를 벗어난 대규모 리팩터링은 하지 않는다.
- 생성된 조회 설정은 기본적으로 불변 스냅샷이다. 센서별 기간은 절대 시각으로 저장하고, 화면에서 조건을 바꿔 공유할 때는 새 View를 만든다.
- 필수 범위는 조회 설정 저장, 채팅 결과 연결, 링크로 화면 복원이다. 이상 구간 판단 결과·분석 근거·알고리즘 버전 보존은 후속 범위다. 시계열 원본이나 분석 알고리즘이 변경되면 조회 설정만으로 과거 분석 결과를 완전히 재현할 수는 없다.

## 통합 완료 기준

- 사용자 질문 → AI 응답 → `chat_result` → `trend_view` → `/trend?viewId=<UUID>` → 센서별 차트의 흐름을 검증한다.
- 진동 7일 + 전압·전류 각 24시간처럼 센서마다 다른 기간이 저장·복원되며, 링크는 새 탭과 새로고침에서도 열린다.
- 일반 URL에서 설비만 지정하면 모든 센서가 표시되고, `sensor_id`가 있으면 해당 센서만 표시된다.
- 접근 권한, 잘못된/없는/만료된 ID, 일부 센서 조회 실패, Tool 재시도 및 저장 실패를 검증한다.
- 최종 보고에는 확인한 구조, 변경 파일/마이그레이션, API 예시, 실제 연결 흐름, 테스트 명령과 결과, 미해결 위험을 기록한다.
