# FE 계획: 대시보드 우선순위와 알람 이력

## 현재 화면과 연결 지점

- Mock 모드의 대시보드는 `alarms` 목록으로 대응 우선순위와 요약을 그린다. 원격 모드는 `App.tsx`에서 대시보드와 설비 화면에 빈 알람 배열을 넘겨 실제 우선순위를 표시하지 않는다.
- 원격 `alarmsQuery`는 `/api/alarms/history`의 모든 페이지를 가져와 60초마다 갱신하고, 알람 이력 화면에서 기간·심각도를 브라우저에서 필터링한다. `alarm-stream.ts`는 SSE 처리 코드가 있지만 실제 원격 구독 연결 여부를 확인해야 한다.
- FE는 [BE 계획](be.md)의 설비별 우선순위 API와 이력 API를 별도 데이터원으로 사용한다. 이력 전체 배열을 현재 활성 순위로 해석하지 않는다.
- [DB 계획](db.md)에 따라 CSV 적재 알람의 `is_active=NULL`은 상태 미확인이다. `alarm_end_time`은 조치 완료, `sensor_end_time`은 센서 복귀이므로 FE에서 둘 중 하나를 알람 해제로 해석하지 않는다.

## 대시보드

1. 플랜트/공정 선택과 서버 `as_of`를 우선순위 조회에 전달하고, 반환된 설비별 순서를 그대로 그린다. 순위는 UI에서 심각도나 설비 등급으로 재정렬하지 않는다.
2. 각 행에 순위, 설비, 대표 센서, CoF, 심각도, 발생 시각, 간결한 이유, 같은 설비의 원본 알람 수와 고유 센서/setpoint 조건 수를 구분해 표시한다. 예측과 임계치 초과가 같은 조건을 가리켜도 설비 행은 하나다. 링크는 `equip_id`·`sensor_id`·`alarm_id`를 포함한다.
3. 활성 건수와 영향 설비 수, 미평가 건수는 BE의 같은 스냅샷에서 가져온다. 우선 확인 카드와 요약 표도 같은 범위/시각을 사용한다. `remoteApi ? []` 분기를 제거하고 원격 응답의 로딩·오류·빈 상태를 화면에 반영한다.
4. `empty`는 “활성 알람 없음”, `unscored`는 “점수 미평가”, `unavailable`은 “상태 확인 불가”로 구분한다. 데이터 로딩/실패를 “이상 없음”으로 표시하지 않는다. 표시 시각은 KST로 변환한다.

## 센서 차트와 Setpoint

- `/api/trend`는 조회 신호·기간과 겹치는 setpoint의 ID, 등급, HIGH/LOW 방향, 연산자, 유효 기간, 계산된 경계값을 제공한다. `FIXED`는 파라미터를 경계값으로 사용한다. `BASELINE_RATIO`, `BASELINE_OFFSET`, `EXPECTED_OFFSET`은 분석기의 참조값·계산 결과가 없으면 경계값을 `null`로 보내고 FE에서 임의 계산하지 않는다. `alarm`의 제거된 실측/기준 컬럼을 경계선 데이터원으로 사용하지 않는다.
- 차트는 전체 표시 구간에 유효한 고정 경계를 등급별 수평선으로 그리고, 경계 바깥 영역을 주의 노랑·경고 주황·위험 빨강·비상 검붉은색으로 채운다. HIGH는 경계 위쪽, LOW는 아래쪽이다. 기간 중 버전이 바뀐 규칙은 단일 수평선으로 그리지 않고 안내한다. 서로 다른 버전의 경계를 전 기간에 적용하지 않는다.
- 실측선과 별개로 유효한 시각·측정값의 최소제곱 선형 추세선을 표시한다. 결측값은 회귀에서 제외하며 표본이 2개 미만이면 추세선을 숨긴다. 추세선은 예측 알람이나 setpoint 판정 결과로 표시하지 않는다.
- 대시보드, 트렌드 상세, 저장된 다중 트렌드의 공통 `TrendChart`에 같은 경계·색상·추세 규칙을 적용한다. 차트 범례와 접근성 설명에 표시 단위와 선의 의미를 적는다. 1시간·1일 평균 차트의 경계 시각과 단위가 원본 1분 판정과 다를 수 있으므로 색 영역을 알람 발생 이력으로 단정하지 않는다.

## 알람 이력과 상세 이동

- 기간, 플랜트, 공정, 설비, 심각도, 알람 유형 필터를 URL과 서버 요청에 함께 반영한다. 새로고침/직접 URL 진입 시 동일 결과를 복원한다.
- 서버 커서 페이지네이션 또는 점진 로딩을 사용한다. 전체 이력을 무제한 로드한 뒤 클라이언트에서만 걸러내지 않는다. 날짜 경계는 서버와 동일한 KST→UTC 규칙을 사용한다.
- 이력 행에는 `alarm_start_time`, 상태, 설비, 센서, 등급, CoF, setpoint ID와 발생 유형을 표시한다. 발생 유형 필터는 `예측`과 `임계치 초과`를 구분한다. Setpoint는 두 유형이 참조할 수 있는 판정 설정으로 표시한다. `alarm` 응답에 실측값·기준값이 없으므로 표의 기존 “실측 / 기준” 열과 원격 응답 어댑터의 필수 필드를 제거한다. 별도 트렌드/판정 근거 조회를 추가할 때만 해당 숫자를 다시 표시한다.
- 알람 행이나 대시보드 링크를 열면 설비 현황의 해당 센서와 알람을 선택한다. 해당 알람의 트렌드/초기 보고서가 있다면 연결하고, 없으면 “없음”을 명시한다.
- 재조회 주기 또는 SSE를 하나의 일관된 최신화 정책으로 정한다. 새 알람/해제 후 순위와 건수를 함께 갱신하고 이전 결과를 잠시 보여줄 때는 마지막 갱신 시각을 노출한다.

## 검증 기준

- 2026-11-19 14:00 KST 원본 자료에서 최고 점수 P1 1.60 > P2 1.20 > P3 1.00 > P4 0.83, 원본 10행·고유 센서/setpoint 조건 6개·영향 설비 4대를 검증한다. P1의 원본 4행은 영향 설비 1대로 집계한다. 활성 근거가 확보된 별도 재생 응답에서 순위를 표시한다. CSV 적재 직후 `is_active=NULL`인 10행은 상태 확인 불가로 표시하고 활성 순위에 올리지 않는다.
- 우선순위/채팅의 1순위와 링크 대상이 일치한다. `alarm_start_time` 매핑과 실측/기준 필드 없는 응답, 필터 URL 새로고침, 페이지 이동, 데이터 없음, 미평가, 조회 실패, 해제 직후 갱신, 모바일 폭을 확인한다.
- Mock 모드의 기존 데모 동작과 원격 모드의 실제 API 표시를 각각 확인하고 화면 테스트 결과를 기록한다.
- FIXED 경계 4등급과 HIGH/LOW 색 영역, 동적 경계 미제공, 유효 기간이 일부만 겹치는 경우, 결측·단일점 추세선, 단위와 KST 시각을 확인한다.
