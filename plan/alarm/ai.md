# AI 계획: 알람 우선순위 설명과 근거 연결

## 현재 흐름

- `alarm_priority` 의도는 Reflector → Action Planner → Executor를 거쳐 BE의 `get_alarm_priorities` Tool을 호출한다. 현재 Executor는 상위 1건 또는 3건을 읽고 CoF, 발생 시각, 측정/기준값과 설비 링크를 답변한다. 계획된 DB 변경 후에는 `alarm_start_time`을 사용하고 알람 행에서 실측/기준 숫자를 읽는 문구를 제거해야 한다.
- AI는 설비 ID, CoF, 등급, 알람 상태를 추측하지 않는다. 데이터 조회와 순위 계산은 [BE 계획](be.md)의 단일 서비스가 담당한다.

## 질문 해석과 범위

- “지금 알람 뭐부터 봐야 해?”는 현재 접근 가능한 범위의 활성 알람을 조회한다. 플랜트/공정/설비가 질문 또는 화면 문맥에 있으면 실제 DB 별칭 조회로 확정하고, 모호하면 후보를 제시한다.
- “1순위만”, “전체 순서”, “P1과 P2 비교”, 과거 시각 질문을 구분한다. 과거 비교는 서버가 지원하는 `as_of` 스냅샷만 사용하고 현재 상태를 과거 사실처럼 말하지 않는다.
- 조회 시각과 범위를 답변에 함께 표시한다. 자료가 없거나 알람 0건, 상태 미확인, CoF 미평가인 경우 각각 다른 문구를 사용한다. “알람 0건”을 “설비 고장 없음”으로 단정하지 않는다.

## 순위 답변과 근거

1. BE가 제공한 설비별 대표 알람 순위를 그대로 사용한다. 한 설비에 알람이 여러 개면 대표 점수와 나머지 활성 건수를 구분한다. 모델이 문장 생성 과정에서 재정렬하지 않는다.
2. 각 순위에는 설비명, 대표 센서, CoF, 심각도, `alarm_start_time`, 판단 이유와 `/equip?equip_id=...&sensor_id=...&alarm_id=...` 링크를 넣는다. 예측과 임계치 초과를 유형 그대로 표현하고, 어떤 `setpoint_id`의 방향·연속 판정 기준을 적용했는지 조회 가능한 경우 근거로 제시한다. `alarm`에서 제거한 실측/기준 숫자는 추측하거나 필수 답변 항목으로 만들지 않는다.
3. CoF가 상대 우선순위용 점수라는 점을 명확히 하고 진단 확정이나 고장 원인으로 표현하지 않는다. 정답지의 고장 유형은 합성 시나리오의 정답이며 AI의 진단 추정과 분리한다.
4. 1순위 초기 보고서를 보여줄 때는 저장된 보고서 스냅샷과 출처를 사용한다. 최근 7일 추이 요약이 없으면 그 사실을 밝히고 임의 관측값을 쓰지 않는다. `maintenance_report`의 기존 실측/기준 문구도 새 계약에 맞춰 삭제하거나 별도 검증된 근거가 있을 때만 표시한다. 점검·정비 제안은 기존 근거 검색 결과와 연결한다.
5. 후속 질문 “그 설비 진동 보여줘”는 직전 답변의 검증된 `equipment_id`·`sensor_id`·`alarm_id`를 사용한다. 다른 설비를 요청하면 문맥을 새로 해석한다.

## 자료 기반 검증

- `plan/alarm/data/README.md`의 2026-11-19 14:00 KST 비교 시각에서 P1 1.60, P2 1.20, P3 1.00, P4 0.83 순서를 답한다. 원본 알람 10행(예측 6·임계치 초과 4), 고유 센서/setpoint 조건 6개, 영향 설비 4대를 혼동하지 않는다.
- P4·P3·P2와 P1 흡입압의 후속 임계치 초과를 앞선 예측과 연결해 설명하되 하나의 사건으로 확정하거나 알람 ID를 합치지 않는다. setpoint의 기준선/기대값 근거가 제공되지 않으면 계산식을 추측하지 않는다.
- P5·P6는 정상 대조군으로 알람을 지어내지 않는다. CoF 누락, 상태 불명, 그룹 밖 설비, 모호한 별칭, 데이터 조회 실패를 테스트한다.
- 링크를 열면 답변의 설비·센서·알람과 일치하며, 답변의 시각·점수·근거가 BE 응답/저장 보고서에서 추적된다.

## 완료 기준

- 대시보드와 AI가 같은 시각·범위에서 같은 1순위를 제시한다.
- 정답지를 모델 프롬프트에 정답으로 주입하지 않고, 관측 데이터와 서버 순위만으로 근거를 구성한다. 문구/툴 결과 테스트 및 남은 모호성을 기록한다.
