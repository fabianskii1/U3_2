# FE 계획: 사건 목록·상세, 차트 표시, 보고서 연결

## 현재 화면

- 라우트는 `/dashboard`, `/equip`, `/trend`, `/alarms`, `/reports`, `/reports/new`, `/reports/:reportId`이다. 사건 화면은 없다.
- 알람은 `features/alarms`(조회·스키마·`AlarmTable`)와 `pages/alarms/AlarmListPage.tsx`에서 다룬다. 차트는 `features/trend`의 공통 `TrendChart`를 쓴다.
- 데이터 계약은 [BE 계획](be.md)을 따른다: `GET /api/incidents`, `GET /api/incidents/{id}`, 알람 이력·우선순위의 `incident_id`·`peak_level`, `/api/trend`의 `incidents` 필드.

## 신규 기능 `features/incidents`

- `api/incidents.schema.ts`(zod), `incidents.queries.ts`(목록·상세), `shared/api/contracts/incident.ts`
- Mock 모드 데이터: 사건 4건, 후보 10행, 알람 10행을 원격 응답 형태로 변환한다. 기존 mock 알람의 시각·CoF도 새 CSV 값으로 바꾼다.
- 등급 색상은 `shared/lib/alarm-level.ts`를 재사용한다.

## 화면

### 1. 사건 목록 (`/incidents`, 네비게이션 추가)

- 컬럼: 상태(진행 중/종료/예정), 시작 시각(KST), 설비, 최고 등급, 선행 센서, 진단, 사건 점수, 대응 등급, 조치 필요, 알람 수
- 필터: 기간, 설비, 최소 등급, 조치 필요, 상태. URL 쿼리와 서버 요청에 함께 반영하고 서버 커서로 페이지를 넘긴다.
- 기본 정렬은 서버 순서(시작 시각 최신순)이며, 사건 점수로 재정렬하지 않는다.

### 2. 사건 상세 (`/incidents/:incidentId`)

- **타임라인**: 사건 시작 → 감지 → 첫 알람 → 종료와 각 간격. 종료 시각이 조회 시각보다 뒤면 "진행 중(예상 종료 …)"으로 표시한다. P3처럼 감지(11-09)와 첫 알람(11-19) 사이가 길면 간격을 강조한다.
- **원인 후보 표**: 순위, 고장명, 점수, p, CoF, PoF, 근거. `is_diagnosis`에는 "진단(추정)", `is_top_risk`에는 "최고 위험" 배지를 단다. `evidence`는 ` / ` 기준으로 나눠 목록으로 보여준다. 후보가 1개뿐이면(P3) "비교 후보 없음"을 표시한다. 점수 구성요소는 펼침 영역에 둔다.
- **관련 알람**: `AlarmTable`을 재사용한다. "등급"(판정 setpoint 등급)과 "최고 도달 등급"(`peak_level`)을 별도 열로 둔다. 예측 알람과 임계치 초과 알람을 구분한다.
- **트렌드 차트**: `trend_window`의 신호를 `TrendChart`로 그린다. 사건 구간 음영, 감지·첫 알람 세로선, 알람 마커, 기존 setpoint 경계선을 표시한다.
- **보고서 작성** 버튼: `/reports/new?incident_id=…`로 이동해 BE 초안을 채운다. 원인 후보에는 "검토 필요"를 표시한다.

### 3. 기존 화면 연결

- **대시보드 우선순위**: BE가 반환한 순서(P1 1.67 > P2 1.0 > P3 1.0 > P4 0.83)를 그대로 그린다. 각 행에 진단명과 "사건 보기" 링크를 추가한다. 사건 점수는 보조 정보로만 표시한다. FE 테스트의 기대 점수를 새 값으로 바꾼다.
- **알람 이력**: `incident_id` 열(사건 링크), 최고 도달 등급 열, 사건 필터를 추가한다.
- **설비 화면(`/equip`)**: 선택 설비의 진행 중 사건 카드와 최근 사건 목록. P5·P6는 "사건 없음"을 표시한다.
- **트렌드 화면(`/trend`)**: `/api/trend`의 `incidents`를 같은 음영 규칙으로 표시하고, 음영을 클릭하면 사건 상세로 이동한다.

## 상태 표시 원칙

- 조회 실패와 "사건 없음"을 구분한다.
- 진행 중 여부는 BE `status`를 그대로 쓰고 FE에서 다시 계산하지 않는다.
- 사건 종료를 "알람 해제"로 표시하지 않는다. 알람의 조치 완료·센서 복귀 시각은 알람 행에서 따로 보여준다.
- 시각은 모두 KST로 표시한다.

## 검증

- vitest: 스키마 파싱(nullable 시각, `peak_level`), 근거 문자열 분리, 타임라인 간격·진행 중 표시
- Playwright(mock): 대시보드 → 사건 상세 → 보고서 초안, 알람 이력 → 사건, 필터 URL 복원
- 원격 모드:
  - P1 상세: 후보 3개, 알람 4개, 진동이 경고선 4.0을 넘는 구간
  - P3 상세: 후보 1개, 토출압이 11/08부터 천천히 떨어지다 11/19 19시대에 급락하는 차트
  - P5 설비 화면: 사건 없음
  - 대시보드 순위 P1 > P2 > P3 > P4와 새 CoF
- 모바일 폭에서 후보 표·알람 표·타임라인이 가로 스크롤 없이 표시되는지
