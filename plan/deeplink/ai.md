# AI 구현: 질문 해석과 Trend View Tool 연동

## 선행 조사

- 실제 LangGraph/LLM Tool 구성, `session`·`session_detail`·`chat_request_log` 저장 흐름, 설비/센서 별칭 조회, 기본 조회 기간 정책을 확인한다. 기존 구조를 확장하고 확인되지 않은 ID나 정책을 가정하지 않는다.
- 사용자 질문과 AI 응답의 연결 방식 및 [BE 저장 API](be.md)에 넘길 서버 검증 실행 컨텍스트를 정한다.

## 의도 해석과 DB 조회

- 사용자 질문의 공장·설비 그룹·설비·센서명/별칭은 DB 조회 Tool로 실제 ID를 확정한다. `2호기 압축기` 같은 표현을 임의 ID로 바꾸지 않는다.
- 표현이 모호하면 후보를 제시하거나 명확화 절차를 사용한다. 모델은 SQL, 센서 ID, URL 경로나 인코딩 문자열을 추측해 만들지 않는다.
- 모델은 구조화된 조회 의도를 만들고, Tool 출력은 Pydantic 등 스키마로 검증한다. 백엔드가 DB Tool 결과와 설비·센서 관계를 재검증한다.
- 시간 범위가 없는 경우 기존 기본 조회 기간 정책을 적용한다. 정책이 없으면 일관된 기본값을 정해 문서화한다.
- `최근 7일`, `24시간` 같은 상대 기간은 서버 기준 시각/타임존으로 **절대 시각**으로 변환한다. 센서마다 다른 기간을 유지하고 같은 센서의 복수 기간도 별도 시리즈로 전달한다.
- 질문 의도에 따라 `showAnomalies`를 설정한다. 탐지 데이터나 분석 결과가 없다면 준비된 것처럼 표현하지 않는다.

## 결과 저장과 응답

1. 구조화된 조회 의도와 검증된 실제 ID·절대 기간을 BE에 전달한다.
2. BE가 `trend_view`와 `chat_result`를 저장한 뒤 발급한 URL을 받는다.
3. 그 URL을 AI 응답의 링크/결과 메타데이터로 전달한다. AI 응답에서 원본 사용자 질문과 결과를 추적 가능하게 한다.
4. 저장 실패 시 유효하지 않은 링크를 반환하지 않는다. Tool 재시도는 BE의 idempotency 정책과 연결한다.

## 범위와 완료 기준

- 필수 범위는 조회 설정 생성, 채팅 결과 연결, 링크 전달이다. 실제 이상 구간·분석 근거·분석 시각·알고리즘 버전을 보존할 `analysis_result`는 선택/후속 범위다.
- 별칭은 실제 DB 식별자로 해석되고 모호하거나 없는 대상은 안전하게 처리된다.
- 진동 7일 + 전압·전류 각 24시간처럼 센서별 절대 기간이 온전히 저장된다. 과거 링크를 나중에 열어도 조회 구간이 바뀌지 않는다.
- 한 AI 응답이 여러 결과를 가질 수 있고, 각 결과에서 응답 및 원본 질문을 추적할 수 있다.
- Tool 재시도·저장 오류에서 중복 결과나 깨진 링크가 생기지 않는다. 통합 테스트 결과를 기록한다.
