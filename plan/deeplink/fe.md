# FE 구현: 채팅 링크와 Trend 화면 복원

## 선행 조사

- 실제 React 라우트, 채팅 응답/결과 렌더링, Trend 페이지, 센서 시계열 조회·캐싱 로직 및 화면 테스트 규칙을 확인한다. 기존 기능을 확장하고 일반 `/trend` URL의 하위 호환을 유지한다.
- [BE API](be.md)의 실제 응답 계약에 맞춰 링크와 화면 상태를 연결한다.

## 채팅 결과 링크

- AI 응답 또는 결과 메타데이터로 받은 서버 생성 URL을 클릭 가능한 `트렌드 보기` 링크로 표시한다.
- 서버가 저장에 실패했다면 유효하지 않은 링크를 표시하지 않는다.

## `/trend?viewId=<UUID>`

- `viewId` 형식을 확인하고 `GET /api/chat/trend-views/{view_id}`로 저장 설정을 복원한다. 현재 세션 쿠키의 경로가 `/api/chat`이므로 이 경로를 사용한다.
- 복원 응답의 `plantId`·`equipmentGroupId`·`equipmentId`를 화면 상단 계층 선택 및 전역 선택 상태에 반영한다. `viewId`만 있는 URL에서도 동일하게 복원한다.
- `viewId`와 `equip_id`·`sensor_id`가 함께 있으면 저장된 `config.series`를 차트 대상으로 우선한다.
- `config.series`의 **모든 항목**을 각 항목의 센서 ID와 개별 `start`·`end`로 조회한다. 첫 항목만 표시하거나 공통 기간으로 덮어쓰지 않는다. 같은 센서의 여러 기간은 별도 시리즈다.
- 센서명·단위·조회 기간을 구분할 수 있는 차트를 각각 제공한다. 기존 센서 시계열 API와 데이터 페칭/캐싱을 재사용한다. `showAnomalies`는 준비된 이상 구간 데이터의 표시 설정으로 처리한다.
- 화면에서 조회 조건을 수정하더라도 원래 View를 변경하지 않는다. 수정 결과를 저장/공유할 때 새 `viewId`를 생성한다.

## 일반 `/trend` URL

- `viewId`가 없고 `/trend?plant_id=PLANT-01&unit_id=CDU-01&equip_id=P2`처럼 설비만 지정되면, P2의 **모든 센서**를 센서별로 조회·표시한다. 새로고침 후에도 동일해야 한다.
- 일반 URL에 `sensor_id`가 명시되면 해당 센서만 표시한다.
- 설비의 모든 센서 표시와 `trend_view.equipment_id`가 없는 그룹 전체 View는 다른 범위다.

## 상태와 제한

- 다중 조회에는 센서별 로딩·오류·데이터 없음 상태를 둔다. 일부 센서 조회가 실패해도 성공한 센서 차트는 표시한다.
- 전체 센서 수와 조회량 제한을 적용한다.
- 잘못된 UUID, 없는/만료된 View, 접근 권한 없음, 삭제·비활성화된 센서, 네트워크 오류를 사용자에게 알맞게 표시한다.

## 완료 기준

- 단일 센서와 서로 다른 기간의 다중 센서가 저장된 조건·단위대로 나타난다. `viewId`와 일반 선택 파라미터가 함께 있으면 저장된 시리즈가 우선한다.
- 일반 URL에서 설비의 전체 센서 및 `sensor_id`로 지정한 센서가 각각 표시된다.
- 링크를 새 탭에서 열거나 새로고침해도 복원되며, 센서 하나의 데이터 없음/조회 실패가 나머지 차트를 막지 않는다.
- 화면 테스트 결과와 미해결 위험을 기록한다.
